Choosing a tier

Every release is identified by its schema letter and date (for example A-2026-11-10) and comes in three tiers built from the same commit. Licensing is per source and per row: each record carries its source’s terms in the License and terms_status columns, and each archive has a LICENSES.md.

TierContainsUse when
byRecords under CC BY 4.0 or in the public domainAttribution must be the only condition (including commercial reuse)
redistributableAll records whose source declares redistributable terms (adds CC BY-SA, CC BY-NC, CC BY-NC-SA, GPL)Research use that can honour NonCommercial and ShareAlike conditions row by row
fullEvery accepted record, including sources whose terms are undeclared (terms_status = missing_declaration)Complete coverage; check the flagged sources before redistribution

Arca’s own identifiers, catalogs, concept/WordNet links and scores are CC BY 4.0. Adaptations of ShareAlike records keep their source’s terms. The code is MIT. Keep original attribution, citations and per-entry URLs.

Rebuilding a release

Each release also ships its accepted-inputs snapshot: unpack it at the root of the repository at the release’s commit and run python build.py update --all and python build.py aggregate to re-derive the data with no other input. Native tables are in data/, a CLDF Wordlist export of the same rows in cldf/.

Citing

Cite the release identifier (and its DOI once minted) together with the original sources of the records you use; each archive includes CITATION.cff and data/sources.bib.
